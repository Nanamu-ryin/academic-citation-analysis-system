# RefHunter 学术引用分析系统

面向阅读英文 STEM 文献的硕博生与青年科研人员的本地桌面引用分析工具：追踪一篇目标论文被哪些后续工作引用、如何引用，并生成逐条可核对证据的分析报告。

## 项目背景

- **目标用户**：需要梳理目标论文被引情况、整理参考文献的研究生与青年科研人员。
- **痛点**：引用数据分散在多个学术来源，需要逐篇下载全文检索题名或作者；人工整理容易漏掉引用、混淆同名作者，也难以判断后续文献是在支持、延伸、对比还是批评原论文。现有被引列表与引用图谱工具通常只给出数量与关系，不提供可逐条核对的原句、前后文与定位信息。

## 产品方案

- **形态**：Windows 本地程序 + `127.0.0.1` 本地 Web 工作台，数据保存在本地，不要求账号与管理员权限。
- **六个模块**：引用获取、PDF 解析、作者身份识别、上下文提取、情感（立场）分析、报告生成。
- **双维独立标注**：
  - 引用功能七类：使用背景、支持、延伸、对比、批评、使用方法或数据、无法判断；
  - 引用立场四类：正面、中立、负面、无法判断；
  - 两个维度分别打标，“批评”属于功能标签，不等同于“负面”立场。
- **证据可追溯**：每条结论保留原文片段、定位来源与证据状态；只有证据充分才标记为“已确认被引”，主题相关或高被引不计入确认。
- **作者识别辅助**：接入 18 类学术荣誉名单进行作者消歧与机构、荣誉信息关联；同名作者标记为待确认，不自动归并。
- **数据源健康检查**：覆盖 18 项来源探测，界面展示各来源状态与限流、超时情况。

## 证据状态

| 状态 | 含义 | 产品行为 |
| --- | --- | --- |
| 已确认被引 | 来源元数据或全文证据能够证明引用关系 | 进入引用列表与报告，展示完整证据链 |
| 已修正被引 | 用户对自动判定的作者、上下文或标签做过校正 | 保留校正痕迹，纳入统计 |
| 可能被引 | 来源提示存在引用，但缺少充分验证 | 单独标记，不计入已确认数量 |
| 无法定位 | 未能获取可核验的上下文 | 保留线索，等待补充 |
| 缺少全文 | 无公开合法全文且用户未提供副本 | 只显示引用线索，不分析原句 |
| 处理失败 | 网络、解析、权限或任务异常 | 可从检查点重试，不覆盖已完成结果 |

## 当前状态（V1.0 实验基线）

已在 Windows 本地跑通界面与多个功能方向，六个模块形成可运行原型；以下数据来自三篇英文样例参考文献与一份中文样本，仅用于方向验证，不作为覆盖率与准确率承诺。

- 英文样例：参考文献命中 **133/139（约 96%）**，其中 124 条含 DOI、100 条含摘要；PDF 链接覆盖由 44% 提升至 78%（109/139）。
- 中文样本：28 条引用仅命中 3 条，摘要覆盖为 0，中文解析能力是已知短板。
- 已知问题：可执行程序启动较慢；任务中断恢复、失败重试与单任务取消尚不完整；数据源探测存在限流与超时。
- 验证情况：尚未经过外部用户的真实任务与耗时验证，项目处于方案 / 原型阶段，未上线，也未开展真实业务访谈。

## 路线图

- **V1.1 可信被引核查闭环**：完善证据定位、人工校正与报告导出；在人工标注集上验证精确率与定位成功率（目标值见 PRD，当前无基线）。
- **V1.2 能力增强**：作者身份消歧、跨论文检索、统计看板、批量任务；增强中文 PDF 参考文献解析。
- **V2.0（未排期）**：账号体系、云端同步、多人协作。
